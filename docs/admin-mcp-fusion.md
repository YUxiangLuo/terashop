# Admin / MCP 联合交付计划

目标：两端共用业务合同，Agent 的操作可由人核对、接管和恢复；不要求每个工具都有独立页面。按 A → D 分批提交，不自动推送或部署。

## A — 合同与能力边界

- [x] 共用无宿主依赖的 scope、金额／税率基础合同，保留各端输入表现与历史读取兼容性。
- [x] 检查工具注册、scope 分类、Admin 路由映射的一致性，明确已有与缺失能力。
- [x] managed-media 作为推荐上传路径，保留既有公开对象核验；不移除兼容工具。
- [x] 核对 Admin 接入配置与远程配置，不把配置展示当作健康证明。公开配置只含 resource/issuer/scopes，生产值仍需部署时核验。

## B — 人工接管的日常操作

- [ ] 客户创建、地址增删改与默认地址；原 ID／请求键恢复，匿名化另属高风险操作。
- [ ] 商品高级字段（条码、成本、原价、标签与 SEO），不覆盖未编辑扩展值。
- [ ] 促销商品／分类／变体搜索选择器，保留 UUID 高级输入。
- [ ] 素材查询、按请求 ID 恢复、未公开素材放弃与删除。
- [ ] 停用仓库库存历史只读核查，不放宽新库存操作资格。
- [ ] 资源导航及安全的业务关联，不通过链接自动执行命令。

## C — 高风险协作

- [ ] 明确可信客户端确认与服务端审批的区别；真实退款、角色变更、匿名化优先。
- [ ] 有限审批绑定身份、资源、原参数、版本及有效期；不接受 Agent 自证批准。
- [ ] 关联 MCP 调用观察与业务资源，保留“返回结果不等于业务结算”的区别。
- [ ] 高风险操作查询／恢复入口，不建设覆盖所有 CRUD 的通用任务系统。
- [ ] Admin 关键操作入口复用相同受控后端；不暴露通用资金重放。

## D — 验收与降噪

- [ ] 串行运行类型、单元、数据库、构建、SQL lint、文档与受影响浏览器回归。
- [ ] 实际渲染检查新增页面及异常状态，保持现有七组导航。
- [ ] Realtime 通知／刷新状态清晰，记录限流与显式重读边界，不承诺可靠事件流。
- [ ] 更新部署、恢复和接入说明，检查生产配置一致性。
- [ ] **外部阻塞**：真实域名、TLS、目标 Agent 客户端、生产配额、备份恢复／密钥轮换演练。需要部署资料与相应授权；本地测试不能代替。

高级元数据 UI、评价运营、统计导出、店铺设置消费端作为后续独立批次评估；批量导入、冻结快照导出、代客下单、Order Edit、多币种、在途调拨和多实例授权服务不属于本次交付。
